Safeguard workflow

Prepare a safe release

Keep the authoritative observation under the data custodian’s control while preparing a representation that matches the recipient’s purpose.

Safeguarding is a sequence of decisions rather than a single button. The owner can create an anonymised layer, encrypt the original or an anonymised representation for selected OpenPGP recipients, upload permitted artefacts to the community, and optionally notarise the resulting package.

Safeguard · 01

Anonymise without overwriting the source

Start with the selected point layer. The authoritative source remains unchanged while MapSafe creates a separate representation for recipients who need spatial patterns but not exact coordinates. The result card can be collapsed so the map remains visible while the owner decides whether to save, repeat, stop, upload, or continue.

Halo masking

Choose minimum and maximum displacement distances. Each point is moved to a random position within that interval. The inverted Spruill score provides a readable indication of parent-nearest disclosure risk; a higher score communicates lower risk.

Hexagonal binning

Choose an H3 resolution and aggregate points into counted hexagons. Darker cells indicate greater density while the individual source coordinates are no longer displayed as the shared representation.

Practical choice: use halo masking when approximate point locations are useful; use hexagonal binning when the recipient needs distribution or density rather than individual points.

Safeguard · 02

Encrypt for selected recipients

MapSafe encrypts the selected dataset once using standard OpenPGP hybrid encryption. A random AES-256 content key protects the payload, and a small public-key envelope is created for each selected recipient. This means one package can be addressed to the custodian, a BMA representative, a researcher, or another authorised community member without repeating the full-payload encryption.

Identity

The local RSA-3072 identity is persistent. Its private key stays on the device and is protected by a passphrase; the public key and fingerprint are the material that can be published.

Recipient decision

Select the intended recipients after checking their fingerprints through a trusted channel. The recipient count changes the envelopes, not the dataset’s underlying content encryption.

  1. Create or recognise the local encryption identity.
  2. Refresh and independently confirm community fingerprints.
  3. Select the original, masked, or binned dataset and intended recipients.
  4. Unlock the signing key and save the resulting .pgp package.
Safeguard · community exchange

Upload only permitted artefacts

After masking or encryption, the owner can choose an artefact for the authorised NextGIS community. Public keys, anonymised layers, and encrypted packages are separate resource types. An unencrypted original is not offered as a community upload. NextGIS Web resource ACLs control who can discover or download the item, while OpenPGP recipient selection controls who can decrypt a protected package.

Keep the controls distinct: community membership does not automatically grant the ability to read every resource, and a user who can download an encrypted package still needs a matching local private key.
Safeguard · 03

Optionally notarise the package

Notarisation is an optional integrity aid. MapSafe calculates the encrypted package’s SHA-256 digest, binds it to the safe package filename, and asks an external wallet to approve the transaction on the selected EVM network. The wallet private key is never collected by MapSafe.

The resulting record supports later comparison of filename and digest. It does not prove that an observation is true, that a person was authorised to publish it, or that a recipient should trust the underlying claim.
